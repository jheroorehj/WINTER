# WINTER

**W**ide **I**maging **N**etwork for **T**argeting **E**ye **R**etinopathy

안저(망막) 사진을 브라우저에서 바로 분석해, **안과 전문의가 아닌 의료진**이 의료취약지역 진료 현장에서 쓸 수 있게 만든 **임상 판단 보조 도구**입니다.

> [!IMPORTANT]
> **이 도구는 진단 기기가 아닙니다.** 화면에 표시되는 값은 공개 안저 데이터로 학습한 모델의
> 통계적 추정치이며, 확진이 아닙니다. 최종 판단은 반드시 의료진의 임상 소견에 따릅니다.
> 화질이 낮거나 산동이 부족하거나 주변부가 포함되지 않은 영상에서는 신뢰도가 떨어집니다.

---

## 무엇을 하는가

전문의가 상주하지 않는 진료 환경에서, 비전문의가 안저 사진을 보고 **"이 환자를 어느 과로, 얼마나 급하게 보내야 하는가"** 를 판단하도록 돕는 것이 목표입니다. 그래서 출력이 병명 하나가 아니라 다음 세 가지입니다.

1. **의심 소견 목록** — **눈별로 분리해서** 그 눈에서 임계값을 넘은 소견을 전부 나열합니다. 한쪽 눈에만 나타나는 질환이 있고 여러 소견이 동반될 수 있으므로, 1순위만 남기지 않습니다.
2. **권장 협진과 시급도** — 어느 과로, 며칠 안에 보내야 하는지.
3. **의뢰 시 전달할 정보** — 추가 검사 권고, 전신질환 연관 경고, 그리고 환자에게 그대로 읽어줄 수 있는 설명 한 줄.

### 2단계 추론 — 당뇨망막병증만 중증도까지

당뇨망막병증은 "있다/없다"로 끝나지 않습니다. 경증 비증식과 증식성은 같은 병명이지만 **경과관찰과 당일 의뢰**로 갈립니다. 그래서 추론을 두 단계로 나눴습니다.

| | 입력 | 출력 | 학습 방식 |
| --- | --- | --- | --- |
| **1단계** | 눈 한 쪽의 안저 영상 | 6클래스 `N,D,G,A,H,O` 소견 유사도 | 다중라벨 (클래스별 sigmoid) |
| **2단계** | 1단계가 `D` 를 의심한 눈만 | 4등급 중증도 `1~4` | 단일라벨 (softmax) |

2단계 등급은 국제 임상 분류(ICDR)와 같은 4단계이며, **시급도가 여기서 나옵니다.** 당뇨망막병증의 시급도를 1단계 유사도(`D` 가 몇 %인가)로 정하면 경증과 증식성이 같은 취급을 받습니다. 그래서 `D` 의 시급도는 유사도가 아니라 등급에서 파생합니다 — 게이트를 넘지 못해 등급이 없는 눈만 유사도 기준으로 떨어집니다.

| 등급 | 이름 | 임상적 의미 | 파생 시급도 |
| --- | --- | --- | --- |
| 1 | 경증 비증식 (Mild NPDR) | 미세혈관류 정도. 혈당 관리 + 연 1회 추적 | 1개월 내 |
| 2 | 중등도 비증식 (Moderate NPDR) | 출혈·삼출물 동반. DME 확인, 6개월 추적 | 1주 내 |
| 3 | 중증 비증식 (Severe NPDR) | 1년 내 증식성 전환 위험 높음 | 즉시 · 72시간 내 |
| 4 | 증식성 (Proliferative DR) | 신혈관·유리체출혈·견인망막박리 위험 | 즉시 · 24시간 내 |

등급은 화면 세 곳에 나타납니다 — 사진 위 오버레이(눈별), 확대 뷰어, 그리고 의심 소견의 `당뇨망막병증` 항목 아래. **모두 눈별로 따로** 표시되며, 양안 등급이 다르면 더 심한 쪽 기준으로 시급도를 정하고 그 사실을 노트로 알립니다.

**1·2위 등급이 근접하면 더 심한 쪽으로 대응합니다.** 인접 등급은 사진만으로 구분이 어렵습니다(2등급과 3등급의 경계는 4-2-1 규칙 같은 정량 기준을 요구합니다). 1위와 2위 차이가 `DR_CLOSE_AT`(0.15) 미만이면 화면이 등급을 단정하지 않고 2위를 함께 적으면서, 시급도는 두 등급 중 더 심한 쪽으로 올립니다. 불확실성을 안전한 방향으로 해소하는 것입니다.

> [!WARNING]
> **2단계는 "당뇨망막병증이 아니다"를 말할 수 없습니다.** 학습 데이터에 `grading_0`(DR 없음) 등급이 없어, 어떤 영상을 넣어도 1~4 중 하나를 냅니다. 1단계가 `D` 를 잘못 의심하면 2단계는 그 위에서 자신 있게 병기를 붙입니다. 그래서 등급은 단독 결론이 아니라 **"1단계가 D 로 의심한 경우의 추정 병기"** 라는 조건부로만 표시하며, 1단계 `D` 유사도가 `DR_GATE`(0.5)를 넘은 눈에만 2단계를 돌립니다. 의심 목록에 `D` 를 올리는 임계값(`SUSPECT_MIN` 0.15)보다 높게 잡은 이유입니다.

여기에 **유사 학습 사례 비교**를 붙였습니다. 모델이 낸 추정치 옆에, 학습 데이터 중 임베딩 공간에서 가장 가까운 확정 진단 영상 3장을 눈별로 함께 보여줍니다. 이웃들의 확정 라벨이 모델의 1순위와 몇 개 일치하는지(`이웃 라벨 일치 2/3`)를 표시하므로, 이웃이 엇갈리면 그 자체가 애매한 케이스라는 신호가 됩니다.

### 설계 원칙: 양안을 하나의 순위로 합치지 않는다

이 도구에서 **환자는 눈 두 개가 아니라 판단 단위 두 개**입니다. 소견을 양안 합산 순위 하나로 접지 않는 것은 표시 취향이 아니라 임상적 요구입니다.

- 같은 소견이 양안에 함께 나타나는 경우가 **오히려 드뭅니다.** 한쪽 눈에만 나타나거나, 두 눈이 서로 다른 소견을 보이는 쪽이 흔합니다.
- 합산하면 한쪽 눈의 소견이 반대쪽 눈의 더 높은 값에 묻히고, **"어느 눈을 먼저 봐야 하는가"** 가 사라집니다.
- 한 환자가 한 가지 병만 갖고 있다고 가정하지 않습니다. 임계값을 넘은 소견은 전부 개별 의심 항목으로 남기고, 임상 보조 정보도 동반 질환을 전제로 만듭니다.

그래서 화면과 의뢰서 텍스트가 이렇게 동작합니다.

| | 동작 |
| --- | --- |
| 의심 소견 | `좌안(OS)` / `우안(OD)` 두 블록으로 분리. 각 소견에 `이 눈에서만` / `양안 공통` 표시 |
| 소견 없는 눈 | 비워 두지 않고 "반대쪽 눈의 소견과 무관하게 판단한 결과"라고 적음 |
| 권장 협진 | 의뢰는 과 단위로 나가므로 과로 묶되, **어느 소견이 이 의뢰를 만들었는지** 눈별 값을 카드에 남김. 시급도는 묶인 소견 중 **가장 급한 것** |
| 동반 소견 경고 | 소견이 2건 이상이면 "단일 진단으로 좁히지 마세요" 노트를 별도로 띄움 |
| 양안 DR 등급 차이 | 더 심한 쪽 기준으로 시급도를 정하되, "반대쪽 눈이 안전하다는 뜻이 아니다"를 명시 |

### 설계 원칙: 신뢰 최대화가 아니라 신뢰 보정

의료 AI 에서 과신은 자동화 편향으로 이어져 환자 위험이 됩니다. 그래서 UI 가 확신을 연출하지 않도록 의도적으로 제약을 걸었습니다.

- 사진 위 추정치는 **단색**으로 표시하고 위험도를 색으로 말하지 않습니다. 사진 위의 붉은 숫자는 확진처럼 읽힙니다.
- 강조는 **값에 비례한 투명도**로만 줍니다. 순위 기반으로 강·약을 주면 `52%` 와 `44%` 처럼 사실상 동률인 값이 확신 차이로 과장됩니다.
- **"확률" 대신 "유사도"** 를 쓰고, 안전 문구를 화면에서 내리지 않습니다.
- 정상 소견 가능성은 의심 목록의 경쟁자가 아니라 **반대 근거**로 따로 적습니다.

## 화면 구성

데스크톱 단일 화면 EMR 입니다. **16:9 비율을 고정**한 채 브라우저 가로 폭에 맞춰 캔버스 전체가 확대·축소됩니다(설계 기준 1920×1080). 레이아웃을 폭마다 다시 짜지 않고 고정 캔버스를 스케일하는 방식이라, 어느 해상도에서든 컴포넌트 배치와 비율이 동일합니다. 1152px보다 좁아지면 글자 가독성이 무너지므로 더 축소하지 않고 가로 스크롤을 허용합니다.

- **1** — 환자명, 나이·성별, 차트번호, 그리고 판단에 필요한 참고 수치만 선별 표시(혈압·HbA1c·기저질환·교정시력 등).
- **2** — 의심 소견(좌안·우안 분리, `D` 항목에는 2단계 등급 동반) → 권장 협진·시급도 → 동반 소견·양안 등급 차이 노트 → 추가 검사 권고 → 전신질환 연관 경고 → 환자 설명용 한 줄 → 안전 문구. 하단에 소견 요약 복사·의뢰서 인쇄.
- **3 / 4** — 좌안·우안 안저 사진. 오른쪽 위에 추정 소견 오버레이와 (해당 눈이 게이트를 넘었으면) DR 중증도 등급, 클릭하면 확대 뷰어에서 휠 확대·드래그 이동. 사진은 임상 열람 관례에 맞춰 좌우반전해 표시합니다.
- **5-7 / 8-10** — 각 눈에 대해 학습 데이터에서 가장 가까운 확정 진단 사례 3장. 클릭하면 현재 환자 영상과 나란히 비교합니다.

## 기술 스택

| 항목 | 선택 |
| --- | --- |
| 배포 | Vercel Free Tier · 정적 웹 호스팅 (HTML/CSS/JS) |
| 추론 | **클라이언트 사이드** — TensorFlow.js 로 브라우저에서 직접 실행 |
| 서버 | 없음. 안저 영상이 단말을 벗어나지 않습니다. |
| 유사 사례 검색 | 홀드아웃 영상의 임베딩을 빌드 타임에 미리 계산해 배포하고, 브라우저에서는 현재 영상 임베딩 1개만 뽑아 거리 계산 |
| 디자인 시스템 | Nocturne (다크 · 저채도 · accent 는 면이 아니라 선으로) |

서버가 없는 구성을 고른 이유는 배포 비용만이 아닙니다. 영상이 업로드되지 않으므로 환자 영상 전송에 따르는 문제가 애초에 생기지 않습니다.

## 저장소 구조

```
WINTER/
├─ index.html                        배포 진입점 (프로토타입으로 연결)
├─ Diabetic retinopathy/             2단계용 DR 등급 영상 65장 (IDRiD, 224×224)
│  └─ grading_1/ … grading_4/         폴더명이 곧 중증도 정답
├─ data/
│  ├─ build.py                        라벨 → 시나리오 빌드 (CSV·JSON·영상·주입)
│  ├─ scenarios.csv                   시연 시나리오 10건 (환자 정보 + 눈별 라벨 + DR 등급)
│  ├─ scenarios.json                  같은 내용의 기계 판독용 사본 + 두 모델의 계약
│  └─ images/                         시나리오별 안저 영상 20장
├─ frontend/project/
│  ├─ 망막분석 EMR.dc.html             ★ 주 설계 파일 (프로토타입 + 로직)
│  ├─ support.js                      프로토타입 런타임 (x-dc)
│  ├─ _ds/nocturne-…/styles.css       디자인 시스템 토큰 + 컴포넌트
│  ├─ sample/                         화면 확인용 안저 샘플 8장
│  └─ uploads/                        와이어프레임
└─ docs/
   ├─ UI_컴포넌트.jpeg                 손그림 와이어프레임 (컴포넌트 1-10)
   ├─ WINTER.png / WINTER 2.png       로고
   └─ 의료진용 …-handoff.zip           원본 핸드오프 번들 (출처 보존용)
```

`망막분석 EMR.dc.html` 은 **프로덕션 코드가 아니라 디자인 프로토타입**입니다. `<sc-for>`, `{{ }}` 바인딩, `DCLogic` 은 `support.js` 전용 문법이므로, 실제 구현은 이 화면의 시각적 출력과 동작을 기준으로 정적 HTML/CSS/JS 로 다시 작성합니다.

### 샘플 안저 영상

화면 확인용 8장을 `frontend/project/sample/` 에 포함했습니다. 파일명은 원본 데이터셋의 레코드 식별자 대신 화면상 역할을 씁니다.

```
frontend/project/sample/
  patient-os.jpg                                      ← 3번 현재 환자 좌안
  patient-od.jpg                                      ← 4번 현재 환자 우안
  similar-os-1.jpg  similar-os-2.jpg  similar-os-3.jpg  ← 5·6·7번 좌안 유사 사례
  similar-od-1.jpg  similar-od-2.jpg  similar-od-3.jpg  ← 8·9·10번 우안 유사 사례
```

**화면의 소견·유사도 수치와는 관계가 없습니다.** 레이아웃 확인용이며, 목업 환자 3명이 같은 8장을 공유하므로 케이스를 전환해도 사진은 바뀌지 않습니다. 경로는 `망막분석 EMR.dc.html` 의 `DEMO_IMG` 한 곳에만 정의돼 있습니다.

공개 안저 데이터셋(`archive/`)의 전처리본 512×512 JPEG 에서 8장을 골랐습니다. 원본 파일명은 데이터셋 레코드 식별자였으므로 화면상 역할이 드러나는 이름으로 바꿨고, EXIF·ICC 프로파일은 원본에 없었으며 추가하지 않았습니다. 영상에 환자 식별 정보는 없고, 화면의 환자명·차트번호·수치는 전부 시연용 가상 데이터입니다.

### 시연 시나리오 — `data/scenarios.csv`

홀드아웃 525명에서 10건을 골랐습니다. 각 시나리오가 UI 설계 결정 하나씩을 증명하도록 구성했습니다. `g1~g4` 는 2단계 중증도 등급입니다.

| # | 시나리오 | OS / OD | 증명하는 것 | 라이브 |
| --- | --- | --- | --- | --- |
| 1 | 양안 정상 | N / N | 정상일 때 정상이라고 말한다 — 과경보 없음 | ○ |
| 2 | 단안 단일 소견 | N / G | 한쪽 눈에만 나타나는 질환. 무증상 진행 | ○ |
| 3 | 단안 복수 소견 | N / A+D `g1` | 한 눈에 두 소견 — 1순위만 남기지 않는 근거 | ○ |
| 4 | 양안 동일 소견 | D `g2` / D `g2` | 양안 대칭은 전신질환 신호 | |
| 5 | 양안 서로 다른 소견 | D `g1` / H | 양안을 한 순위로 합치면 깨지는 케이스 | ○ |
| 6 | 양안 모두 복수 소견 | D+G `g2` / D+G `g2` | 소견 4개를 순위로 누르지 않고 보여주기 | |
| 7 | 양안 일부 겹침 | H+O / H | 양안 공통 소견 + 한쪽만의 추가 소견이 묻히지 않는가 | ○ |
| 8 | DR 경증 · 단안 | D `g1` / N | 2단계가 경증이라고 말하면 시급도가 내려간다 | ○ |
| 9 | DR 인접 등급 | D `g3` / D `g2` | 한 단계 차이는 사진만으로 구분이 어렵다 — 등급을 단정하지 않는 근거 | |
| 10 | 증식성 DR | D `g3` / D `g4` | 최고 등급 경로. 눈별 등급이 다르면 더 심한 쪽 기준 | ○ |

**8~10 은 1단계 라벨이 앞의 시나리오와 겹칩니다.** 8은 `D / N`, 9와 10은 `D / D` 라서 1단계 출력만으로는 각각 5번·4번과 구분되지 않습니다. 겹치는 것이 요점입니다 — 등급이 붙어야 "1년 내 재촬영"과 "오늘 바로 의뢰"가 갈립니다. 2단계가 없으면 이 세 환자는 같은 화면을 받습니다.

4개 등급이 모두 시연에 등장합니다 (g1 3눈 · g2 5눈 · g3 2눈 · g4 1눈).

**눈별 라벨은 파생값입니다.** 데이터셋의 `N,D,G,C,A,H,M,O` 8개 컬럼은 환자 단위이고 눈별 정보는 자유 텍스트 진단 키워드에만 있습니다. 그래서 단일라벨 + 양안 키워드 동일 환자만 골라 키워드→클래스 매핑을 역추론했고(18종 전부 100% 일관), 그 매핑으로 눈별 라벨을 만들었습니다. `drusen` 은 A 가 아니라 O 로 떨어집니다. 검증할 수 있도록 원문 키워드를 `os_keywords` / `od_keywords` 에 그대로 남겼습니다.

#### D 인 눈의 영상은 IDRiD 로 교체합니다

2단계 모델은 IDRiD(`Diabetic retinopathy/`)로 학습하므로, 시연 영상도 같은 분포에 두지 않으면 등급 출력을 신뢰할 수 없습니다. 그래서 **`D` 가 유일한 소견인 눈**은 영상을 `grading_N/` 에서 가져옵니다. 어느 등급 폴더에서 가져올지는 그 눈의 ODIR 키워드가 정합니다.

```
mild nonproliferative retinopathy       → grading_1
moderate non proliferative retinopathy  → grading_2
severe nonproliferative retinopathy     → grading_3
proliferative diabetic retinopathy      → grading_4
```

즉 **ODIR 키워드와 IDRiD 폴더가 같은 등급을 가리킬 때만** 그 영상을 씁니다. 둘이 어긋나면 빌드가 실패합니다. 중증도가 적히지 않은 `diabetic retinopathy` 키워드(홀드아웃 12건)는 매핑에서 일부러 빼, 등급을 추측한 데이터가 섞이지 않게 했습니다.

**동반 소견이 있는 눈은 교체하지 않습니다.** 시나리오 3(`A+D`)과 6(`D+G`)이 그렇습니다. IDRiD 영상에는 황반변성·녹내장 소견의 근거가 없으므로, 교체하면 없는 소견을 있다고 말하는 데이터가 됩니다. 이 눈들은 ODIR 영상을 유지하고 등급은 키워드에서만 가져옵니다 — `os_dr_grade_source` / `od_dr_grade_source` 열이 `idrid_folder`(폴더로 검증됨, 8눈)와 `odir_keyword`(키워드만, 3눈)를 구분합니다.

교체 범위는 `build.py` 의 `DR_IMAGE_SWAP` 한 줄로 바꿉니다.

| 값 | 동작 |
| --- | --- |
| `'pure_d_eye'` (현재) | `D` 단독인 눈이면 교체. 4개 등급 전부가 IDRiD 로 검증됨 |
| `'pure_d_patient'` | 양안이 모두 `D` 단독일 때만 교체. 한 환자 안에서 데이터셋이 섞이지 않음 |
| `'off'` | 교체하지 않음. 등급 정답은 ODIR 키워드만 사용 |

> [!NOTE]
> **현재 설정에서 시나리오 5·8 은 한 환자의 두 눈이 서로 다른 데이터셋에서 옵니다.** IDRiD 에는 정상 안저(`grading_0`)도 고혈압성 망막병증도 없어서, `D / N` 이나 `D / H` 조합은 한쪽 눈을 ODIR 에서 가져올 수밖에 없습니다. 두 눈의 색조·화각·해상도(224 vs 512)가 눈에 보이게 다릅니다. 화면 일관성을 우선한다면 `DR_IMAGE_SWAP = 'pure_d_patient'` 로 바꾸면 되고, 그 대가로 1등급은 IDRiD 검증 없이 ODIR 키워드만 근거로 남습니다. 지금은 **2단계가 실제로 맞는 등급을 내는 것**을 우선해 `'pure_d_eye'` 를 씁니다.

**환자 기록은 ODIR, D 인 눈의 영상은 IDRiD 인 합성 레코드입니다.** 나이·성별·눈별 라벨·동반 소견은 ODIR 홀드아웃 환자의 실제 값이고, `D` 단독 눈의 영상만 같은 등급의 IDRiD 영상으로 바뀝니다. 어느 눈이 어느 데이터셋에서 왔는지는 `os_dataset` / `od_dataset` 열에, 원본 파일명은 `os_source_file` / `od_source_file` 열에 남아 있어 전부 역추적됩니다.

**실제 데이터는 나이·성별·영상·라벨뿐입니다.** 화면 상단의 혈압·HbA1c·기저질환·교정시력·복용약, 그리고 환자명·차트번호·방문일·기관명·환자 설명 문장은 모두 **생성한 가상 정보**입니다. 각 시나리오의 실제 라벨과 임상적으로 정합되게 만들었습니다(당뇨망막병증 케이스에 HbA1c 상승, 고혈압성 케이스에 혈압 상승 등). 어느 열이 가상인지는 CSV 의 `clinical_fields_synthetic` 열에 명시돼 있습니다.

주요 열:

```
scenario_no  scenario_key  scenario_name  demo_primary  proves
patient_id  age  sex  patient_level_labels                    ← 실제
os_image  od_image  os_labels  od_labels                      ← 실제(라벨은 파생)
os_dr_grade  od_dr_grade  dr_pattern                          ← 실제(2단계 등급, 파생)
os_dataset  od_dataset                                        ← 영상 출처 (ODIR-5K | IDRiD)
os_dr_grade_source  od_dr_grade_source                        ← 등급 근거 (idrid_folder | odir_keyword)
os_keywords  od_keywords  os_artifact  od_artifact            ← 실제 원문(역추적용)
os_source_file  od_source_file                                ← 실제 원본 파일명
display_name  chart_no  visit_date  site                      ← 가상
weight_bmi  blood_pressure  hba1c  history                    ← 가상
corrected_vision  medication  vital_notes  patient_line        ← 가상
clinical_fields_synthetic                                     ← 가상 열 목록
```

`dr_pattern` 은 양안 등급 관계입니다 — `none`(D 없음) · `unilateral`(한쪽만) · `bilateral_same_grade` · `bilateral_diff_grade`. 양안 등급이 다를 때 화면이 무엇을 기준으로 시급도를 정하는지가 여기서 갈립니다.

10건 모두 1단계가 추론 가능한 6클래스(`N,D,G,A,H,O`) 안에 있습니다. 라벨셋 밖 소견(백내장·근시)이 포함된 환자 57명은 제외했습니다. 6개 클래스와 4개 등급이 모두 시연에 등장합니다.

`data/build.py` 가 원본 라벨에서 눈별 라벨과 2단계 등급을 파생시켜 `scenarios.csv`·`scenarios.json` 을 쓰고, 영상을 복사하고, 프로토타입의 `SCENARIOS` 블록까지 주입합니다. 시나리오를 추가하려면 `build.py` 의 `SCENARIOS` 에 항목 하나만 넣고 다시 돌리면 됩니다.

```
python3 data/build.py
```

다음 중 하나라도 어긋나면 빌드가 실패합니다.

- 선언한 `pattern` 이 실제 눈별 라벨에서 파생된 유형과 다르다
- 선언한 `dr=` 등급이 그 눈의 키워드에서 파생된 등급과 다르다
- `D` 인 눈인데 중증도 키워드가 없어 등급을 정할 수 없다
- `D` 가 아닌 눈에 DR 중증도 키워드가 붙어 있다
- 등급이 있는데 `dr=` 선언을 빼먹었다
- 6클래스 밖 소견이 섞였다
- 영상 파일이 없거나, 해당 등급 폴더에 배정할 장이 남지 않았다

IDRiD 영상은 한 장이 두 눈에 재사용되지 않고, 배정 시작 위치를 `scenario_no` 로만 정하므로 **시나리오를 중간에 끼워 넣어도 기존 시나리오의 영상이 바뀌지 않습니다.** ODIR 원본(`test_dataset_seed42/`, `archive/`)은 `.gitignore` 로 제외돼 있어 데이터셋을 가진 로컬에서만 실행됩니다.

### 모델 연결 지점

프로토타입은 연결 준비만 된 상태입니다. 화면은 목업 추정치로 동작하고, 모델이 준비되면 함수 두 개만 교체하면 됩니다.

교체할 곳은 `MODEL` 객체의 두 메서드뿐입니다. 그 아래 화면 로직은 **길이 6 확률 벡터**만 알고 모델은 모릅니다.

| 지점 | 현재 | 교체 후 |
| --- | --- | --- |
| `MODEL.load()` | 즉시 resolve | `tf.loadLayersModel(MODEL_URL)` + 워밍업 |
| `MODEL.infer(imgUrl, hint)` | 정답 라벨 기반 결정적 목업 벡터 | 영상 → 텐서 → `net.predict()` → `Array` |
| `neighbors(sc, eye, preds)` | 검출 라벨에 맞춘 플레이스홀더 (영상도 실제 이웃이 아님) | 사전계산 임베딩 kNN |
| `DR_MODEL.load()` | 즉시 resolve | `tf.loadLayersModel(DR_MODEL_URL)` + 워밍업 |
| `DR_MODEL.infer(imgUrl, hint)` | 정답 등급 기반 결정적 목업 벡터 (길이 4, 합 1) | 영상 → 텐서 → `net.predict()` → `Array` |

2단계 게이팅과 화면 표시는 **이미 연결돼 있습니다.** `inferScenario()` 가 1단계를 먼저 끝내고, `D` 유사도가 `DR_GATE` 를 넘은 눈에만 `DR_MODEL.infer()` 를 호출해 `toGrade()` 로 넘깁니다. 게이트를 넘지 못한 눈은 등급이 `null` 이고 화면이 그 이유를 적습니다 — 값이 비어 있는 것이 아니라 "돌리지 않았다"가 결과입니다.

`infer` 의 두 번째 인자 `hint` 는 **목업 전용**(정답 라벨)입니다. 실제 구현은 영상만 보고 이 인자를 무시해야 합니다 — 참조가 남으면 정답을 훔쳐보는 추론이 됩니다.

**라벨 순서와 학습 방식이 계약입니다.**

```js
const LABEL_ORDER = ['N', 'D', 'G', 'A', 'H', 'O'];   // 출력 벡터 순서와 1:1
const MODEL_MULTILABEL = true;                         // 클래스별 sigmoid + BCE
const MODEL_INPUT = { size: 224, channels: 3, scale: 1/255, mean: null, std: null };
```

**반드시 다중라벨(sigmoid)로 학습해야 합니다.** 한 눈에 두 소견이 동시에 존재하는 케이스가 홀드아웃에 실제로 있습니다(시나리오 3의 `A+D`, 7의 `H+O`). softmax 로 학습하면 확률이 서로를 밀어내 "의심 소견을 전부 나열한다"는 이 화면의 전제가 깨집니다. 확률의 합은 1이 아닙니다.

전처리 규격(`MODEL_INPUT`)이 학습 때와 하나라도 다르면 추론이 **조용히** 틀립니다. 오류가 나지 않으므로 값을 맞춰서 넘겨주세요.

**2단계 모델의 계약은 1단계와 다릅니다.** 같은 파일에 별도 상수로 두었습니다.

```js
const DR_GRADE_ORDER = [1, 2, 3, 4];                   // 출력 벡터 순서와 1:1
const DR_MODEL_MULTILABEL = false;                     // 상호배타 4분류 — softmax + CE
const DR_MODEL_INPUT = { size: 224, channels: 3, scale: 1/255, mean: null, std: null };
const DR_MODEL_URL = '../../data/model-dr/model.json';
const DR_GATE = 0.5;                                   // 1단계 D 유사도가 이 값을 넘은 눈만
const DR_CONDITIONAL_ONLY = true;                      // 등급은 단독 결론이 아니다
```

1단계는 다중라벨이지만 **2단계는 반드시 단일라벨(softmax)로 학습해야 합니다.** 한 눈이 경증이면서 동시에 증식성일 수는 없습니다 — 병기는 하나입니다. 2단계까지 sigmoid 로 학습하면 등급이 서로를 배제하지 않아 "2등급 0.7 · 3등급 0.6" 처럼 해석 불가능한 출력이 나옵니다.

두 모델의 전처리 입력 크기는 둘 다 224 이지만 **같은 모델이 아니므로 가중치를 공유하지 않습니다.** 산출물은 `data/model/`(1단계)과 `data/model-dr/`(2단계)로 나뉩니다. 둘 다 아직 없습니다.

## 한계

- 안저 사진 한 장으로 판단할 수 없는 질환이 있습니다. 안압·시야검사·OCT 가 필요한 경우 화면이 그렇게 안내합니다.
- **2단계는 "당뇨망막병증 없음"을 출력할 수 없습니다.** 학습 데이터에 해당 등급이 없습니다. 1단계의 `D` 오탐 위에서는 2단계도 반드시 틀립니다.
- **2단계 등급의 인접 단계는 사진만으로 구분이 어렵습니다.** 특히 중등도(2)와 중증(3)의 경계는 4-2-1 규칙 같은 정량 기준을 요구하며, 224×224 로 줄인 영상에서는 판단 근거가 남지 않을 수 있습니다. 등급을 단정하지 않고 인접 등급 분포를 함께 보여줘야 하는 이유입니다(시나리오 9).
- 시연 영상의 해상도가 균일하지 않습니다. ODIR 전처리본은 512×512, IDRiD 등급 영상은 224×224 입니다. 확대 뷰어에서 후자가 더 흐리게 보입니다 — 모델 입력이 224 라 정보량 차이는 없지만 화면 인상은 다릅니다.
- 화질이 낮은 영상에서는 추정 신뢰도가 떨어집니다. 이 경우 재촬영이 판단보다 우선입니다.
- 유사도는 모델 임베딩 공간상의 거리이며, **동일 진단을 의미하지 않습니다.**
- 시나리오 10건의 환자명·차트번호·임상 수치는 시연용 가상 정보이며 실제 환자가 아닙니다. 나이·성별·눈별 라벨·DR 등급만 실제 데이터입니다.
